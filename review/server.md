# Review: agentgraph-server (HTTP/SSE surface)

**Reviewer:** Reviewer_Server (staff-level Rust backend reviewer, READ-ONLY review)
**Scope:** `agentgraph-server/src/` (`lib.rs`, `routes.rs`, `runs.rs`, `sse.rs`, `auth.rs`, `error.rs`, `assistants.rs`, `crons.rs`, `store.rs`, `server_store.rs`) + `agentgraph-server/examples/server_demo.rs`
**Verdict (overall):** A well-structured, honestly documented axum service with a thoughtful tenant model and clean multitask scheduler — but the tenant isolation has one real cross-tenant lookup hole, the durability story is broken at the thread layer (memory-only thread records over durable checkpoints), the rollback endpoint silently no-ops on the Postgres backend, and the cron scheduler can be killed or turned into a fire-storm by a single crafted `interval_secs`.

## Explicitly verified clean

- **Auth middleware vs. CORS ordering:** correct. `.layer(auth)` is applied first (inner), `CorsLayer::permissive()` second (outermost), so OPTIONS preflights are answered by tower-http before the API-key middleware runs, and actual cross-origin requests still pass through auth. The code comment (routes.rs:138-141) matches the tower layer semantics. (The exposure of permissive CORS + no-auth defaults is finding #12, not an ordering bug.)
- **Tenant prefix spoofing via crafted ids on creation paths:** `validate_client_id` blocks `/`, `\`, empties, all-dots, >256 chars on every client-chosen id (thread/assistant/cron); KV segments are stricter still (`[A-Za-z0-9._-]`, 128 max, all-dots rejected — store.rs:32-46). `strip_owned` correctly refuses prefix-substring confusion (`"acm"` does not match `"acme/..."`, unit-tested at auth.rs:172) and gives the default tenant exactly the unprefixed ids. The one hole in the scheme is the unvalidated `assistant_id` body field (finding #1), plus reserved-name layout collisions (finding #8).
- **Tenant spoofing via checkpoint ids:** `checkpoint.checkpoint_id` replay is looked up via `get_by_id` within the caller's already-scoped thread namespace (routes.rs:550-564); checkpoint ids are server-minted UUIDs, never path-joined with client input. Clean.
- **Cross-tenant run access:** both `GET /runs/{id}` and the rollback endpoint check `tenant.owns(&info.thread_id)` and answer 404 (not 403) cross-tenant — no existence leak. Clean.
- **RunManager lock granularity:** the tokio `Mutex<RunManagerInner>` is never held across `.await` in `insert`/`snapshot`/`info`/`finish` — all critical sections are synchronous map operations. FrameSink's std Mutexes are held for nanosecond-scale critical sections only (clone/push). No lock-across-await hazard. (The poison-`expect` robustness issue is finding #6.)
- **SSE replay bounds:** the event log is bounded (`event_log_capacity`, default 1000, floor 16), broadcast channel is 256, lagged receivers are warned and skipped rather than blocked. Replay-then-live chaining correctly dedups by `seq`. Clean within its design (the design itself is finding #10).
- **Cron expression validation:** 5-field exprs are pinned to second 0 (`format!("0 {expr}")`) and parsed at creation; unparseable exprs 400. 6-field input fails parse. Clean. (The interval path is finding #4.)
- **Postgres SQL:** all `server_*` statements use bound parameters; migration is advisory-lock serialized; the KV upsert's `created` flag correctly drives 201 vs 200; no string interpolation anywhere. Clean.
- **TODO/FIXME/placeholder leftovers:** none in any reviewed file.
- **`expect("serialization is infallible")` sites** (assistants.rs:85, crons.rs:169, store.rs:91): accurate — `serde_json::Value`-containing structs serialize to JSON without fallible paths. Acceptable.
- **Example (`server_demo.rs`):** clean — scripted model with sensible "done" fallback, honest `unwrap()`s appropriate for example code, curl cheatsheet matches the actual routes.

## Top 5 must-fixes

1. **Cross-tenant assistant resolution** (`routes.rs:519-548`) — `RunPayload.assistant_id` is scoped without `validate_client_id`; since the default tenant's `scope()` is identity, `"assistant_id": "acme/a1"` lets the default tenant probe **and run** another tenant's assistant. 3. **Cron `interval_secs` overflow DoS** (`crons.rs:88-111`) — unbounded input: values > `i64::MAX` wrap negative → fire-storm every 200 ms tick; large positive values panic chrono's `Add` inside the single scheduler task → **all** crons of all tenants stop firing silently.
