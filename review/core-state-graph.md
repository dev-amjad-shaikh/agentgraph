# Review: Core State & Graph (`agentgraph/src/{state,node,graph,error}.rs`)

**Reviewer:** Reviewer_Core_StateGraph (staff-level, read-only)
**Scope:** `agentgraph/src/state.rs`, `agentgraph/src/node.rs`, `agentgraph/src/graph.rs`, `agentgraph/src/error.rs` (+ inline tests). Cross-checked usage in `agentgraph/src/executor.rs` for two findings (merge ordering, `END` const).

## Findings

| # | file:line | severity | category | current gist | concrete fix |
|---|-----------|----------|----------|--------------|--------------|
| 1 | state.rs:316-320, 367-373 (with executor.rs:604, 696) | **must-fix** | correctness / reducer merge | `apply_super_step` merges in input iteration order; the executor builds `writes` from a `tokio::task::JoinSet`, i.e. **completion order**. `Append`/`AddMessages` fan-in therefore produces **run-to-run nondeterministic state** (and nondeterministic checkpoints) with no warning anywhere in the docs. | Canonicalize order before merging: sort `collected` by node name in `apply_super_step` (or require/ sort in the executor), document that multi-write fan-in order is deterministic-by-node-name, and add a test asserting stable output regardless of input order. |
| 2 | graph.rs:234-239, 285-324 | **must-fix** | correctness / validation gap | `add_edge` twice with the same `from → to` (or two conditional edges from one node) is accepted by `compile()`; the target can then be activated **twice in one super-step**, and if it writes an `Overwrite` channel the run fails with a spurious `InvalidUpdate` — a runtime failure the compile gate promised to exclude. | In `compile()`, reject exact duplicate `Direct(from,to)` edges and duplicate conditional edges per source (dedupe via `HashSet<(String,String)>` / `HashSet<String>`); add a compile-failure test. |

## Overall verdict per file

| file | verdict |
|------|---------|
| `agentgraph/src/state.rs` | **Good core with one real correctness exposure.** Reducer semantics, LastValue validation, and error messages are well thought out and well tested. But fan-in merge order is silently nondeterministic under the actual executor (must-fix #1), and there are several defensive patterns that mask type bugs (silent array coercion, `reducer_for` default, unreachable duplicate check). Doc comments are strong overall but occasionally narrate mechanics instead of invariants. Fix #1 and #3 before calling this production-grade. |
| `agentgraph/src/node.rs` | **Cleanest file of the four.** The blanket impl, `Arc<dyn Node>` impl, and interrupt/resume protocol docs (including the idempotency contract) are exactly what a staff reviewer wants to see. Only polish-level issues: a doc overstatement about snapshot sharing, a `&self` method that doesn't use `self`, an `ignore`d doc example, and the `update`/`updates` naming near-collision. No correctness concerns. |
| `agentgraph/src/graph.rs` | **Solid builder, but the validation gate under-delivers relative to its own docs.** The module header promises structural validation "before any node ever runs", yet duplicate edges, direct+conditional mixes, sentinel-name collisions, and unreachable nodes all pass `compile()` — and the headline `END` constant is dead public API whose doc describes behavior that doesn't exist. The `ConditionalRouter` type alias with the explicit `Send`-shadowing NOTE is a nice touch. Close the validation gaps or trim the promises. |
| `agentgraph/src/error.rs` | **Functional but the weakest file.** The `Interrupt`-as-error design is well justified in the docs, and `is_interrupt`/`interrupt_value` are the right helpers. However, every other variant is stringly-typed: sources are destroyed at construction, node names travel by comment-convention, and there is no `From<io::Error>` for checkpoint IO. Fine for a whitepaper companion crate; insufficient for a library whose callers need programmatic error handling. |

## Final summary for orchestrator


**Counts by severity:** must-fix **2** · should-fix **7** · nit **16** (25 findings total)

**Top must-fixes** (both):
1. **state.rs:367-373 + executor.rs:604/696 — nondeterministic fan-in merge order.** `apply_super_step` merges in input order; the executor feeds it `JoinSet` completion order, so `Append`/`AddMessages` results (and checkpoints) differ run-to-run. Fix: sort writes canonically (e.g. by node name) before merge + determinism test.
2. **graph.rs:234-239/285-324 — duplicate edges pass `compile()`.** Identical `from→to` edges (or two conditional edges from one node) double-activate the target, producing a spurious `InvalidUpdate` at runtime on `Overwrite` channels. Fix: reject duplicates in `compile()`.

(Next tier, should-fix: silent array coercion in `AddMessages`/`Append` reducers · dead `END` const with a false doc claim · `__end__` sentinel name not reserved · stringly-typed error variants losing sources · `reducer_for` silent `Overwrite` default · unreachable `seen_in_node` defensive check · unenforced "don't mix static + dynamic edges" warning.)
